# Installation and setup

Install Talaria on both machines:

- the **controller**, which starts and manages work; and
- the **workstation**, which owns the repositories and runs coding-agent CLIs.

## Requirements

- Node.js 20 or newer on both machines
- Tailscale connectivity between them
- OpenSSH or Tailscale with the `tailscale ssh` CLI
- enabled coding-agent CLIs on the workstation
- tmux 3 or newer on the workstation for sessions that survive disconnects

Without tmux, Talaria uses direct child processes. That fallback is non-persistent.

## Install

```sh
npm install -g talaria
talaria --version
```

On the workstation, authenticate every coding tool you intend to enable for the account that will run Talaria.

OpenCode is available as the `opencode` built-in. Install and authenticate its CLI with
`opencode auth login`, then select `opencode` during setup or enable it later with
`talaria server add-tool opencode`.

To install a development checkout instead:

```sh
git clone https://github.com/MFoxx/talaria.git
cd talaria
npm install
npm run build
npm link
```

## Guided setup

Run `talaria setup` on each machine. Choose `server` on the workstation and `client` on the controller. The wizard checks prerequisites, writes configuration, and previews transport-specific changes.

Server setup accepts multiple allowed directories. Each permits that directory and descendants after symlinks are resolved. Prefer absolute paths. A leading `~` expands for the server account; Talaria does not expand environment variables or `~otheruser`.

Config defaults to `~/.config/talaria/{client,server}.json`; sessions and logs default to `~/.local/share/talaria/`.

## OpenSSH over Tailscale

Use this mode when command-level isolation matters. Talaria installs a dedicated public-key entry restricted to `talaria serve`, with shell access, PTYs, and forwarding disabled.

```sh
# Workstation
talaria setup --role server --transport openssh --tool codex \
  --allowed-dir /Users/me/projects

# Controller
talaria setup --role client --transport openssh \
  --host my-workstation --ssh-user me
```

Repeat `--tool` and `--allowed-dir` as needed. In the wizard, paste the key generated by client setup into server setup. For flag-driven setup, install the printed restricted `authorized_keys` line manually.

Forced commands do not load shell startup files, so setup pins absolute paths for Node, Talaria, and built-in tools. Build and link a source checkout before setup. Invoking setup through `tsx src/cli.ts` cannot produce a runnable sshd forced command.

If you install another supported CLI later, enable it locally on the workstation without rerunning setup:

```sh
talaria server add-tool grok
```

The command resolves and pins the executable, adds the tool to the server allowlist, and refreshes the PATH in Talaria's restricted OpenSSH key entries. It leaves unrelated `authorized_keys` entries unchanged.

Cursor is discovered as `cursor-agent`, with a validated fallback to the legacy `agent` name. Talaria rejects an `agent` command that identifies itself as Grok Build and refuses to pin two tools to the same executable. Remove a stale or incorrect pin with `talaria server remove-tool cursor`.

### Cursor beta: macOS keychain authentication

Cursor support is beta. On macOS, Cursor may store its login in the user's login keychain. A Talaria OpenSSH forced command runs outside the interactive graphical login context, so Cursor can fail with:

```text
Error: Your macOS login keychain is locked.
```

Unlock the keychain interactively on the workstation, then retry:

```sh
security unlock-keychain "$HOME/Library/Keychains/login.keychain-db"
talaria tools
```

Cursor recommends `CURSOR_API_KEY` for headless execution, but Talaria does not yet provide secure tool-specific secret injection. A project `.env`, shell profile, or terminal `export` is not automatically loaded by the OpenSSH forced command. Do not store API keys directly in `server.json`. This limitation will be revisited in a future release.

Tailscale SSH intercepts tailnet port 22 and bypasses OpenSSH `authorized_keys`. Setup detects this conflict. Choose Tailscale SSH or deliberately disable it first:

```sh
tailscale set --ssh=false
```

## Tailscale SSH

This mode avoids SSH key and host-key management:

```sh
# Workstation
talaria setup --role server --transport tailscale-ssh --tool codex \
  --allowed-dir /Users/me/projects
tailscale set --ssh=true

# Controller
talaria setup --role client --transport tailscale-ssh \
  --host my-workstation --ssh-user talaria
```

Configure tailnet network and SSH rules so only the intended controller identity or tag can reach the workstation as the exact server OS user. An `accept` SSH rule supports unattended calls; a `check` rule may demand interactive reauthentication. Avoid broad access such as `autogroup:nonroot`.

Tailscale SSH cannot enforce an `authorized_keys` forced command. On macOS, interactive setup can create a hidden, password-disabled, non-admin `talaria` account with a restricted shell. It previews changes, grants access only to configured project roots, installs a self-contained runtime when required, and verifies tools as the service account.

Authenticate coding CLIs as that account. If a tool lives below a private home directory it cannot traverse, install it in `/opt/homebrew`, `/usr/local`, or another shared prefix; setup will not weaken home-directory permissions.

On other operating systems, setup retains the selected/current account. Prefer OpenSSH where forced-command isolation is required. The macOS App Store/TestFlight Tailscale build lacks the required CLI wrapper; use Tailscale's standalone distribution on the controller.

If Talaria is absent from the workstation's non-interactive path, give the client the exact command:

```sh
talaria setup --role client --transport tailscale-ssh \
  --host my-workstation --ssh-user me \
  --server-command '/absolute/path/to/node /absolute/path/to/talaria/dist/cli.js serve'
```

## Verify

```sh
talaria ping -H desktop
talaria tools -H desktop
talaria run -H desktop -t codex -d /absolute/allowed/project \
  -p "Summarize this repository"
```

If the host is `defaultHost`, omit `-H`. `talaria config` prints resolved client configuration; redact identities and private paths before sharing it.

See the official [Tailscale SSH documentation](https://tailscale.com/docs/features/tailscale-ssh) for policy details.
